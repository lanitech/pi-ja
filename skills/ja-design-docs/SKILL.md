# 日本語の設計書を作る

開発前に仕様を日本語の文書にまとめるためのスキルです。3 種類の雛形があります。

| 文書 | 雛形 | 出力先の既定 |
| --- | --- | --- |
| 要件定義書 | `references/requirements.md` | `docs/requirements.md` |
| 画面一覧 | `references/screens.md` | `docs/screens.md` |
| データ設計 | `references/data-model.md` | `docs/data-model.md` |

## 進め方

1. 頼まれた文書の雛形を読む。種類が指定されていなければ、要件定義書 → 画面一覧 → データ設計の順で作る。
2. リポジトリにすでに設計書があるか確認する（`docs/`、`README.md`、`AGENTS.md`）。あれば新しく作らず、その文書を更新する。
3. 既存のコード・スキーマ・ルーティングから読み取れることは先に埋める。推測で埋めない。
4. 分からない項目は空欄にせず「未定：〇〇を確認」と書き、最後にユーザーへの確認事項としてまとめて聞く。
5. 3 つの文書の ID をそろえる。要件 ID（`REQ-01`）、画面 ID（`SCR-01`）、テーブル名は文書をまたいで同じものを使う。
6. 書き終えたら、作ったファイルと「未定」の項目の数を報告する。

## 書き方のルール

- 文体は体言止め・である調でよい。プロジェクトに既存の文書があれば、その文体に合わせる。
- 1 行 1 項目。表で書けるものは表にする。
- 日付は YYYY-MM-DD。英数字は半角。
- テーブル名・カラム名・API パスは英語（snake_case）、説明は日本語。
- 図が必要なら Mermaid のコードブロックで書く（ER 図は `erDiagram`、画面遷移は `flowchart`）。
- 雛形の見出しのうち、明らかに不要なものは削ってよい。削ったことは報告に書く。
